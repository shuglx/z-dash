01 · 技术方案
路由Hash 路由单页应用（#/todo #/archive #/links），三个视图按需渲染；刷新/后退可用，无需服务器配置
响应式断点 820px：PC 显示左侧导航栏，移动端隐藏并显示底部 Tab 栏；任务看板 PC 三列、移动单列（上下滑动切栏）
数据层data/ 目录 JSON 文件为唯一数据源，三级读写策略：
① FS Access 实时读写（首选）— File System Access API 授权 data/ 目录（showDirectoryPicker），handle 存 IndexedDB，之后所有增删改直接写回 JSON 文件，Chrome/Edge 首次授权后免重复授权（需 localhost 或 http）
② localStorage 缓存 + 「导出 JSON」手动落盘（Safari/Firefox 兜底）
③ file:// 直开：只读展示，改动仅进 localStorage
离线零 CDN 依赖：系统等宽字体栈、纯手写 CSS、原生 JS（无框架）；图标用字符/内联 SVG
拖拽HTML5 Drag & Drop（PC）+ 长按拖动降级（移动端用按钮切状态兜底）
// 目录结构

// todos.json 数据结构
{ "version": 1,
  "items": [
    { "id": "t-0001", "title": "修复 CI flaky test",
      "status": "todo|doing|done", "priority": "P0|P1|P2",
      "project": "infra", "dueDate": "2026-08-21",
      "createdAt": "...", "doneAt": "2026-08-19T10:32:00" } ] }
// archive.json —— 归档时从 todos 移入，带完成时间（日历按 doneAt 打点）
{ "version": 1, "items": [ { "id", "title", "project",
  "doneAt": "2026-08-19", "archivedAt": "..." } ] }
// links.json —— 分组结构，groupId=null 表示未分组
{ "version": 1,
  "groups": [ { "id": "g-01", "name": "DEV", "collapsed": false } ],
  "items": [ { "id": "l-0001", "title": "GitHub",
    "url": "https://github.com", "groupId": "g-01" } ] }

说明：纯静态站点浏览器无法直接写本地 JSON 文件，故采用「JSON 文件为源 + localStorage 运行时缓存 + 一键导出覆盖」的方案；若后续接受 file:// 直开，fetch 需换成本地嵌入门帘（<script> 注入 data），方案里两者都会兼容。
